Alive Video · documentation de référence · état au 23 octobre 2026

Alive Video,
la documentation

La même application qu'Alive-Comics, en version vidéo : on découpe une planche en cases, on dépose une vidéo dans chaque case, on règle couleurs, cadrage, vitesse et une pile d'effets, et la planche entière sort en un seul fichier MP4. Ce document dit tout ce qu'il faut pour l'utiliser, la faire évoluer ou la reprendre ailleurs. À lire avec CLAUDE.md (consignes pour Claude Code).

1vidéo (ou image) par case
7effets empilables, + opacité, vitesse, envers, volume
1calcul : le lecteur (WebGL) et l'export (NumPy) font les mêmes passes
~1/255écart moyen mesuré entre lecteur et export
0génération : ni H3, ni ComfyUI, ni IA

1 · Le concept

Une page de BD qui est une vidéo

  • Une planche garde tout d'une page de BD : des cases (découpage façon komawari, traits penchés), des gouttières, un ordre de lecture. Chaque case contient une vidéo (ou une image fixe).
  • Toutes les cases jouent ensemble sur une seule horloge, celle de la page : l'aperçu montre exactement la vidéo qui sera exportée. Un mode « au survol » garde l'esprit d'Alive-Comics (une case joue sous la souris).
  • Chaque case a ses réglages : couleur, cadrage, début et fin, boucle, vitesse, lecture à l'envers, opacité, volume, et une pile d'effets (flou, couleur, N&B · sépia · teinte, vignette, grain, halation, aberration chromatique).
  • Sortie : la page entière en MP4 (durée, résolution et images par seconde au choix), les sons des vidéos, les sons ajoutés et la musique de la page mélangés. Ou la page jouable en HTML (page seule, livre), publiée par lien.
  • Rien n'est généré : les vidéos sont celles de l'auteur. Aucune clé d'IA, aucune machine de calcul.

2 · Démarrer

Lancer, passer sur un autre PC

  1. Outils

    Python 3.10 ou plus, Git, et ffmpeg / ffprobe dans le PATH (import des vidéos, export).

  2. Code
    git clone https://github.com/grosdada/Alive-Video.git
cd Alive-Video
pip install -r requirements.txt        # pillow, numpy, opencv-python-headless
  3. Lancer

    Lancer_Alive_Video.bat (ou python -m app), puis http://127.0.0.1:8792. Port 8792 : Alive-Comics garde le 8790, les deux tournent côte à côte. Un second lancement ouvre juste le navigateur (port exclusif). Instance de test : python tools/dev_instance.py → port 8793 (mêmes dossiers : tester sur une copie zz-…).

  4. Sur un Mac

    Dans le Terminal : curl -fsSL https://raw.githubusercontent.com/grosdada/Alive-Video/main/mac/install.sh | bash. Le script (mac/install.sh) installe Homebrew s'il manque (mot de passe de la session demandé), Python 3.12, ffmpeg et git, clone le dépôt dans ~/Alive-Video, crée l'environnement Python .venv et le raccourci « Alive Video » sur le Bureau, qui lance Lancer_Alive_Video.command (mise à jour git pull au lancement si le Mac est en ligne). Relancer la même ligne met à jour. Rien n'est téléchargé par le navigateur : pas de blocage Gatekeeper.

  5. Application Mac (DMG)

    Les données peuvent vivre hors du code : variable ALIVE_HOME (app/paths.py) pour projects/, data/ et local_settings.json ; le code (app/, player/) reste en lecture seule. Consigne de fabrication d'un « Alive Video.app » autonome en DMG pour Claude sur Mac : mac/BRIEF-DMG.md.

  6. Ou sans rien installer

    Ouvrir l'application d'un autre poste, par le réseau : sur le PC qui la fait tourner, "server": {"host": "0.0.0.0"} dans local_settings.json et le port 8792 ouvert dans le pare-feu ; puis http://<adresse du PC>:8792 (à la maison, ou par Tailscale). Les planches restent sur ce PC.

  7. Ce qui n'est pas dans Git

    projects/ (planches, vidéos importées, copies de lecture, exports), data/ (livres, projets de rangement, préréglages, registre des publications, journal), local_settings.json (port, publication). Les copier pour changer de PC ; ne jamais les versionner.

Au niveau de la planche : name, page (format, sens, taille, fond, traits, gouttière, marge), layout (arbre de découpes, chaque trait avec son id), anim (cadrage animé, § 7 bis), geometry (cases calculées, page finie), pageSound (musique), export {duration (null = auto), height, fps}, published, rev.

Qui écrit quoi : l'application garde la main sur le découpage, les médias et le cadrage ; le serveur et l'aperçu sur edit, extraSounds, review, export et published (un enregistrement de la planche ne les remplace jamais, sauf pour une case nouvelle, qui garde ce que l'application y a recopié en changeant de découpage).

5 · Dans l'application

Fabriquer une planche

Page et découpage (inchangés)

  • Formats : page BD, manga, 4:5, carré, écran 9:16 ; vertical ou horizontal.
  • Découpages prêts ou au hasard ; glisser un trait le déplace, glisser un bout l'incline (Maj : droit) ; couper, supprimer, pivoter ; fond, traits, gouttière, marge ; Ctrl+Z / Ctrl+Y.

Chaque case

  • Glisser une vidéo (ou une image) sur la case, ou cliquer. L'éditeur montre l'affiche (première image) ; molette pour zoomer, glisser pour recadrer.
  • Icônes de la case : média, filtres (ouvre l'éditeur de case dans l'aperçu), sons. Étiquette : durée du passage, vitesse, envers, nombre d'effets.
  • Inspecteur : infos de la vidéo, cadrage, « Lecture et effets » (vitesse, en boucle, à l'envers, volume, opacité, résumé de la pile), sons ajoutés.

Barre du haut : Exporter la vidéo, Aperçu, ✏️ Éditer (aperçu en mode édition), 📁 Dossier, Publier, ⚙ Réglages (publication). Réglages de page (rien de sélectionné) : format, couleurs, traits, musique de la page, résumé de l'export.

6 · Les vidéos

Original, copie de lecture, copie à l'envers

  • L'original reste intact dans assets/ : l'export le relit en pleine qualité.
  • Le lecteur lit une copie (app/media.py) : H.264, 1280 px au plus, images/s constantes (celles de l'original, 60 au plus), une image clé toutes les 15, AAC stéréo. Faite à l'import, en une seconde environ par seconde de vidéo HD.
  • Mêmes images : la copie et l'export appliquent le même filtre fps à l'original ; l'image n de la copie est l'image n de l'export (temps = n / fps).
  • Mêmes couleurs : la copie passe par le RGB tel que ffmpeg lit l'original, puis est convertie en BT.709 et balisée en entier (matrice, primaires, transfert, plage). L'export relit l'original de la même façon. Une vidéo sans balise de couleur est donc vue pareil des deux côtés.
  • Rotation des téléphones appliquée, pixels non carrés corrigés.
  • Lecture inversée : copie à l'envers faite à la demande (morceaux de 2 s retournés puis mis bout à bout, le son retourné d'un bloc). Le filtre reverse de ffmpeg garde tout en mémoire : jamais sur une vidéo entière.

Le temps d'une case (identique dans le lecteur et l'export)

n = images de la vidéo ; [a, b] = début / fin (toute la vidéo par défaut) ; L = b - a + 1
k = floor(t × vitesse × fps + 1e-6)            t = temps de la case (celui de la page)
en boucle : k = k mod L     une fois : k = min(k, L - 1)  (puis l'image reste figée)
image = b - k si à l'envers, sinon a + k

Durée de la page (aperçu et export) : réglée à l'export, ou automatique = le plus long passage (L / fps / vitesse) ; 5 s s'il n'y a pas de vidéo. La page boucle à cette durée.

7 · Retoucher

L'éditeur de case

Dans l'aperçu servi par l'application : « ✏️ Éditer », puis un clic sur une case (ou directement ?edit=1&case=p3, ce que fait l'icône filtres). La case est montrée agrandie, calculée comme dans la page. Tout est enregistré au fil de l'eau (0,7 s après le dernier geste) ; « ↺ Annuler mes retouches » revient à l'ouverture. Barre espace : lecture / pause de toute la page.

OngletContenu
Lecture (vidéo)Bande d'images (glisser : voir une image, la page s'y cale), poignées début / fin, « Début ici », « Fin ici », « Tout le clip » ; en boucle ou une fois ; vitesse.
CouleurSaturation, luminosité, contraste, température, teinte ; « Neutre » ; « Appliquer à toute la page ». Passe avant les effets.
CadrageZoom, horizontal, vertical (dans les marges disponibles : on ne sort jamais de l'image) ; l'image de la page suit.
FiltresOpacité, vitesse, lecture inversée, volume ; puis la pile : « ＋ Ajouter un effet » (flou, couleur, N&B · sépia · teinte, vignette, grain, halation, aberration chromatique), chaque effet avec ses réglages, ▲ ▼ pour l'ordre (appliqués de haut en bas), ● pour le couper sans le retirer, ✕ pour le retirer ; « 💾 Enregistrer la pile » (préréglage pour toutes les planches, ★ pour l'appliquer) ; « Copier les effets sur toute la page ».
SonVolume du son de la vidéo ; sons ajoutés (volume, boucle ou une fois, retirer, glisser un fichier) ; musique de la page (importer, remplacer, retirer, volume).

Aussi : pastilles de suivi sur chaque case et compteur page / livre ; fenêtre déplaçable et agrandissable ; « 🏠 Accueil » et « ✎ Planche ».

La capture de l'autre logiciel (onglets Transform | Effects | Anim) n'est pas arrivée avec la demande : l'onglet Filtres suit la liste écrite (effets ajoutés à la demande, réglés, empilés ; opacité, vitesse, envers, volume). À ajuster sur la capture si la présentation doit coller davantage.

7 bis · Le découpage qui bouge

Animate framing

Les traits des cases s'animent dans le temps : une case s'ouvre, une autre se dédouble, un trait bascule. Bouton 🎞 Animate framing dans la barre du haut de l'éditeur de planche : une timeline s'ouvre sous la planche.

  • Une ligne par point d'attache : chaque trait a deux bouts (gauche / droit pour un trait horizontal, haut / bas pour un vertical), donc deux lignes ; les losanges sont les images clés.
  • Toucher une attache dans la planche met la timeline sur sa ligne (la poignée du milieu : les deux lignes du trait), et le trait passe en évidence.
  • Glisser une attache pose une clé à l'instant de la tête de lecture. La première clé d'une ligne en pose aussi une à 0 s avec la position de départ : le trait part de là où il était. En mode animation, une case peut se refermer entièrement (trait collé au bord) : elle disparaît à ces instants.
  • Timeline : clic = tête de lecture ; glisser un losange = changer son instant ; double-clic = une clé ; « ◆ Clé ici » ; « Courbe » de la clé choisie (douce, linéaire, accélère, ralentit, palier : la courbe vaut jusqu'à la clé suivante) ; « ✕ Clé » ou Suppr ; « Effacer le trait » (il garde sa position du moment) ; barre espace = lecture. Les clés tombent sur les images de la vidéo exportée.
  • Hors du mode : la planche montre la page finie (fin de l'animation) ; glisser un trait animé décale toute son animation. Un nouveau découpage retire l'animation (Ctrl+Z la rend).
  • La vidéo d'une case suit sa case : elle la remplit toujours (couverture × zoom du cadrage), recadrée à chaque instant.
  • Durée automatique de la page : au moins la fin de l'animation + 1 s.

Données : chaque trait (split de layout) a un id (c1, c2…) ; project.anim = {tracks: {"c2.a": [{t, v, e}]}} (t en secondes, v de 0 à 1 comme a / b, e = courbe). Interpolation identique dans app/web/js/geometry.js (éditeur), player/alive-player.js (lecteur : la page entière, fond, cases vides et traits compris, est alors dessinée par le canevas) et app/geometry.py (export : cases recalculées à chaque image, sources décodées entières puis lues au placement du moment). Contrôle lecteur / export sur une page animée : 1 à 2,4 / 255 d'écart moyen, traits au même pixel.

8 · Le calcul

Les effets, formule par formule

Une seule définition, deux exécutions : les shaders FS de player/alive-player.js et app/effects.py. Toute modification d'un côté doit être faite de l'autre.

  • Grille d'une case : alignée sur les pixels de la sortie, de floor(x0 × échelle) à ceil(x1 × échelle) ; coordonnées u, v de 0 à 1 sur cette grille, v = 0 en haut. Poser la case dans la page ne rééchantillonne donc rien.
  • Passes : source placée + couleur de base, puis un passage par effet, chacun arrondi à 8 bits (une texture RGBA 8 bits dans le lecteur, q8() dans l'export) ; enfin la case est posée dans son polygone (élargi sous le trait), l'opacité mélangeant avec la couleur du fond.
  • Unité des tailles : un millième de la hauteur de la page. Même rendu à l'écran et en 4K.
EffetRéglagesFormule
Couleur (et onglet Couleur)exposition (IL), contraste, saturation, température, vert ↔ magenta, teintec × 2^IL ; (c − 0,5) × contraste + 0,5 ; mélange avec la luma Rec. 709 ; + (0,07, 0, −0,07) × temp + (0,05, −0,06, 0,05) × teinte ; rotation autour de l'axe des gris. Tout est affine : une matrice 3 × 4 dans l'export.
Flourayon (σ en unités)Gaussienne séparable (horizontale puis verticale), rayon ⌈3σ⌉, bords prolongés. Au-delà de σ = 6 px : réduction d'un facteur ⌈σ / 6⌉ (bilinéaire, centres alignés), flou à σ / f, agrandissement bilinéaire, des deux côtés.
N&B · sépia · teintemode, couleur, intensitéN&B : luma ; sépia : matrice classique bornée ; teinte : noir → couleur au gris moyen → blanc. Mélange par l'intensité.
Vignetteintensité, taille, douceurd = |2(uv − 0,5)| / √2 ; c × (1 − intensité × smoothstep((d − taille) / douceur)) (ellipse qui suit la case).
Grainintensité, taille, animéBruit 256 × 256 commun (player/grain.png), échantillonné en bilinéaire répété à uv × taille de la case en unités / taille + décalage ; décalage de la suite R2 pour l'image n de la page (n = temps × fps de l'export) et la graine de la case ; c + (g − 0,5) × intensité × 0,6.
Halationintensité, seuil, rayon, couleurh = clamp((luma − seuil) / (1 − seuil)), flouté (comme le flou) ; c + couleur × h × intensité × 2.
Aberration chromatiquedécalage (unités au coin)Rouge lu à 0,5 + (uv − 0,5)(1 + k), bleu à (1 − k), vert en place ; k = décalage / demi-diagonale de la case.
Opacité · vitesse · envers · volume—Opacité : mélange avec le fond de page. Vitesse et envers : règle du temps (§ 6) ; le son suit (hauteur gardée). Volume : gain du son de la vidéo.

9 · Ce que voit le lecteur

Le lecteur

  • Page = page.jpg (fond, cases, affiches) + un canevas WebGL (WebGL 2 si possible : mipmaps pour réduire les vidéos) + frames.png (traits) par-dessus. Vues supplémentaires (éditeur de case, agrandissement au double-clic) : leur propre canevas.
  • Les vidéos jouent nativement (le son vient d'elles) et se recalent sur l'horloge de la page quand elles dérivent de plus de 0,25 s ; en pause, l'image exacte est affichée. Une texture n'est recalculée que si une nouvelle image est arrivée, si un réglage a changé ou si le grain change d'image.
  • Barre de lecture : lecture / pause (barre espace), position (glisser), temps ; « Tout » ou « Au survol ».
  • Son : bouton « Activer le son » (règle des navigateurs : rien avant le premier geste), « Son » coupe tout ; noir et blanc, plein écran, livre (flèches, clavier, balayage).

10 · Sortie

L'export vidéo

  1. Réglages

    Durée (auto = le plus long passage, ou en secondes, 10 min au plus), résolution par le petit côté (480p, 720p, 1080p, 1440p, 4K : une page BD 2:3 en 1080p donne 1080 × 1620, un écran 9:16 1080 × 1920), images par seconde (24, 25, 30, 50, 60). Gardés dans la planche.

  2. Préparation

    Page jouable remise à jour (sons égalisés), fond et traits dessinés à la résolution de l'export (traits en onglet, comme le canevas), puis chaque vidéo décodée une fois dans l'original : filtre fps, début / fin, mise à l'échelle de son placement (zone pour réduire, bilinéaire pour agrandir), recadrée sur la case, en images brutes sur le disque (lues ensuite à volonté : boucle, envers, vitesse).

  3. Rendu

    Chaque image : chaque case calculée par effects.py, posée dans la page, traits par-dessus ; plusieurs images en parallèle (fils), envoyées à x264 (CRF 18, BT.709). Mesure : 3 cases, 7 effets, 1080 × 1920, ~0,08 s par image sur 7 fils (25 s pour 10 s de vidéo à 30 im/s).

  4. Son

    Piste de chaque vidéo (début / fin, envers, atempo pour la vitesse, volume, en boucle ou une fois puis silence), sons ajoutés et musique de la page (les fichiers égalisés du lecteur), mélangés sans normalisation, limiteur à −0,2 dB, AAC 192 kb/s.

  5. Fichier

    projects/<id>/video/<nom>-<date>.mp4 (H.264 + AAC, faststart). Un export à la fois, suivi dans la fenêtre (avancement, temps restant) et par une pastille à l'accueil. Les exports ne sont jamais effacés.

11 · Même résultat

Contrôle lecteur / export

Le lecteur capture la page à un instant donné, à la taille de l'export (AlivePlayer.capture : vidéos calées sur l'image exacte), le serveur calcule la même image et donne l'écart par case, loin des traits (POST /api/projects/<id>/compare?t=…, images dans compare/). Dans la console de l'aperçu :

const inst = [...AlivePlayer._pages][0], [PW, PH] = inst.data.size, k = 1080 / Math.min(PW, PH);
const ev = (x) => Math.max(2, Math.round(x / 2) * 2);
const cv = await AlivePlayer.capture(inst, 2.0, ev(PW * k), ev(PH * k));
const blob = await new Promise(ok => cv.toBlob(ok, "image/png"));
await (await fetch(location.pathname.replace(/export\/.*/, "").replace("/projects/", "/api/projects/") + "compare?t=2", { method: "POST", body: blob })).json();

12 · S'y retrouver

L'accueil, les livres, la publication

  • Identiques à Alive-Comics : onglets Planches | Livres, vignettes ou liste, recherche, tris, étoiles d'après les pastilles, projets de rangement (glisser une planche sur un projet ; data/folders.json), livres repliables (pages réordonnées, aperçu, édition dans le livre, publication).
  • Pastille « ● export 42 % » sur la planche (et sur ses livres) pendant un export.
  • Publication par SSH (Réglages : adresse du site, hôte, utilisateur, dossier, clé du poste). Rien n'est réglé par défaut : Alive-Video a besoin de son propre dossier en ligne (la clé par défaut est celle d'Alive-Comics, ~/.ssh/alive_comics_hostinger, déjà connue de l'hébergement).

14 · Le tri

Ce qui a été retiré d'Alive-Comics

Retiré

  • MiniMax H3 : arcs, orbite 360, demi-arcs, travellings, boucles, prompts, régénération, variantes.
  • ComfyUI, fal, la file de rendus, les machines, l'indice de mouvement.
  • Le relief (cartes de profondeur), les couches (SAM, BiRefNet, Qwen, LaMa, Depth Pro), Lytro.
  • Le réalisateur IA, l'IA de case, la traduction ; la génération de sons (MiniMax Music, voix IA, bruitages).
  • Le tremblé et les retouches propres aux boucles H3 (ralentis, fondu au raccord, aller-retour).

Gardé

  • Le découpage des planches, l'accueil, les projets de rangement, les livres, la publication.
  • L'édition de la page ; par case : couleurs, cadrage, vitesse (et désormais début / fin, boucle, envers, opacité, volume, filtres).
  • Les sons importés sans doublon, la musique de page, les pastilles de suivi et les étoiles.

15 · Mémoire

Leçons, limites et pistes

  • « Même résultat » tient parce que les deux côtés font les mêmes passes sur la même grille, arrondies pareil : ne jamais ajouter un effet d'un seul côté. Rejouer le contrôle (§ 11) après toute retouche d'un shader ou de effects.py.
  • Poser une case dans la page sans rééchantillonner (grille alignée sur les pixels) a divisé l'écart et le temps de calcul ; la couleur en une matrice affine aussi (6 fois plus rapide, identique à 2·10⁻⁷ près).
  • ffmpeg : balises de couleur à poser sur les images (setparams) ; les options -color_primaries seules ne suffisent pas. -shortest au mixage final coupait la dernière image.
  • Volet de navigateur caché : requestAnimationFrame ralentit ; pour une capture, le remplacer par un MessageChannel (comme dans Alive-Comics).
  • Pistes : export d'un livre entier en une vidéo (pages à la suite), fondus entre pages ; aperçu de l'export (/still) comme vignette de l'accueil ; volume au-delà de 100 % (il faudrait WebAudio, muet en file://) ; animation du cadrage dans le temps (onglet « Anim » de l'autre logiciel) ; décalage du départ d'une case dans la page.
